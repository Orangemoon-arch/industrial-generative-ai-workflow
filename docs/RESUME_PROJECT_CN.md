# 中文简历项目说明

本页用于把仓库中的工程事实转换为简历和面试语言。数字均来自已完成的实验、测试或公开仓库，不代表生产环境指标。

## 推荐项目名称

**工业生成式 AI 工作流｜独立开发**

技术栈：Python、PyTorch、FastAPI、Gradio、ERNIE-Image、Qwen3-VL、Hunyuan3D、trimesh、PyMeshLab、GitHub Actions

项目链接：<https://github.com/Orangemoon-arch/industrial-generative-ai-workflow>

## 简历版（推荐）

面向工业零件生成与 3D 打印验证，独立搭建从文本需求、图片生成、视觉质量检查、透明遮罩、单图/多图三维重建，到网格诊断、分级修复和 STL 导出的可追踪工作流。

- 在 RTX 3060 12GB 上部署并顺序验证 ERNIE-Image、Qwen3-VL-8B 和 Hunyuan3D 单图/多视图推理，通过 NF4 量化、CPU offload 与短生命周期子进程控制资源，最高计算进程显存约 6.89 GiB。
- 使用 Gradio 与 FastAPI 开发任务工作台和接口，覆盖候选生成、人工确认、遮罩检查、三维生成、网格复核、修复及产物下载；通过文件锁、单线程队列和 GPU 预检避免模型并发争用。
- 设计版本化任务清单，记录输入、请求、日志、阶段产物和 SHA256；增加任务内路径校验、修复试算、失败回滚及人工接受/拒绝门禁，避免原始 GLB 被自动覆盖。
- 基于 trimesh/PyMeshLab 实现水密性、连通部件、边界边、非流形边和退化面检查，以及小孔限制、独立伪影清理、局部换边和表面距离门禁；真实案例将连通部件由 2 个降至 1 个、退化面由 1 个降至 0。
- 建立 78 项服务层测试与 24 项几何专项测试，并接入 GitHub Actions；提供无需 GPU 和模型权重即可复现的 CPU Demo，验证修复前后报告及源文件 SHA256 不变。

## 一页简历精简版

- 独立开发工业生成式 AI 工作流，串联 ERNIE-Image、Qwen3-VL 与 Hunyuan3D，覆盖文生图、视觉检查、图生 3D、网格修复和 STL 导出，并在 RTX 3060 12GB 上完成顺序推理验证。
- 基于 Gradio/FastAPI 实现版本化任务工作台，以 GPU 预检、文件锁、单线程队列、SHA256 校验、失败回滚和人工门禁保证流程可追踪且不覆盖原始产物。
- 实现网格拓扑诊断与分级修复，真实案例实现连通部件 2→1、退化面 1→0；累计 102 项自动化测试通过，并通过 GitHub Actions 持续验证。

## 30 秒面试介绍

“这个项目是我独立完成的工业生成式 AI 工作流。它不是简单把三个模型串起来，而是解决生成结果如何进入工程流程的问题。我在一张 RTX 3060 12GB 上顺序运行文生图、视觉语言和图生三维模型，用 Gradio 和 FastAPI 做了任务工作台，并为每一步保存版本、日志和 SHA256。三维输出还会经过拓扑检查、分级修复和人工接受门禁。项目目前有 102 项自动化测试和一个不依赖 GPU 的公开 Demo，面试官可以直接在 GitHub 上验证核心修复逻辑。”

## 面试展开顺序

1. 先讲限制：只有一张 12GB 显卡，三个大模型不能同时驻留。
2. 再讲架构：模型顺序运行，任务状态与产物版本化，页面只负责组织流程。
3. 重点讲工程判断：水密和单连通不等于尺寸、齿形或装配正确，因此保留人工门禁。
4. 用修复案例收尾：原模型不覆盖，候选先试算；指标通过后仍需人工接受。
5. 主动说明边界：这是实习期原型，不是生产系统；精确功能件应转向参数化 CAD 或结构重建。

## 表述边界

- 可以写“独立开发”“原型”“部署并验证”“端到端流程”和“自动化测试”。
- 不要写“训练了 ERNIE/Qwen/Hunyuan”；本项目主要是部署、推理适配和工作流工程。
- 不要写“工业级”或“已投入生产”；当前是实习期研究与竞赛流程验证原型。
- 不要把水密、单连通写成“机械尺寸正确”或“可直接打印”；尺寸、公差、齿形和装配仍需工程确认。
- 若投算法研究岗，应坦诚本项目优势在多模型集成、系统工程和几何后处理，而不是基础模型训练。
